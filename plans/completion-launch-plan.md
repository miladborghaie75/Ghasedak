## ۲) پروتکل اجرای هر گام + قواعد کیفیت

1. **تأیید وضعیت فعلی:** کد/داده را دوباره بخوان؛ آیتم‌های ❓ را اول قطعی کن.
2. **اقدام:** تغییر حداقلی و هم‌سو با قواعد پروژه (schema/runtime جدا؛ بدون dependency جدید بی‌دلیل؛ بدون fallback پنهان).
3. **تست:** تست‌های مرتبط موجود + تست جدید رگرسیون (برای باگ‌ها الزامی). برای UI: شاهد تصویری قبل/بعد.
4. **شاهد runtime:** خروجی تست/کنسول/لاگ/DB/اسکرین‌شات — چیزی که ثابت کند قابلیت واقعاً کار می‌کند.
5. **به‌روزرسانی اسناد:** همین فایل (وضعیت + شاهد) + `docs/implementation-status.md` اگر دامنهٔ تغییر دارد.
6. **کامیت:** پس از تأیید شما، کامیت کوچک با پیام شامل شناسهٔ گام (مثل `[F0-1]`).

7. **دروازهٔ تست ایستگاه (الزامی — خواستهٔ شما):** با پایان گام‌های هر ایستگاه و **قبل از شروع ایستگاه بعد**: اجرای تست ایستگاه (جدول پایین) + بازرسی تصویری صفحات متأثر + بررسی کنسول/لاگ + ثبت شاهد → **هر ایراد همان‌جا رفع می‌شود**؛ ایراد زمان‌بر به‌عنوان آیتم جدید در همان ایستگاه ثبت و تا سبزی حل می‌شود. **هیچ ایستگاهی با ایراد باز عبور نمی‌کند** و ایستگاه بعد شروع نمی‌شود.

**قواعد کیفیت:** تست ضعیف/غیرفعال، سرکوب خطا و suppressor اضافه ممنوع؛ اگر رفتاری عوض شد تستش هم با توضیح می‌عوضد. هیچ سری/کلیدی commit نمی‌شود؛ env جدید → `.env.example` هم به‌روز. تغییرات uncommitted فعلی (دیف پرداخت و تست‌ها) کارِ این جلسه نیست و دست نمی‌خورد تا گام ۰ تعیین تکلیف کند.

**دروازهٔ خروج هر ایستگاه (تست + فیکس الزامی):**

uptime-check واقعی روی دامنهٔ اصلی + تست رسیدن هشدار (شبیه‌سازی down؛ شاهد: دریافت پیام در تلگرام/ایمیل) + هشدار دیسک/CPU/RAM و `5xx` + بازهٔ نگهداری/بروزرسانی. **پذیرش:** هشدار تستی واقعاً رسید. **اندازه:** S

#### گام ۳۹ — `[F4-6]` دادهٔ واقعی محصولات — ⬜
پاک‌سازی دادهٔ تست/دمو (محصولات تست، کاربران DEMO→واقعی، رسانه‌های بی‌صاحب)؛ سپس ورود گروهی کاتالوگ واقعی (گام ۱۳) + تصاویر (گام ۹) + دسته/برند/قیمت‌گذاری کانال‌ها. **اندازه:** L

#### گام ۴۰ — `[F4-7]` سرویس‌ها + مانیتورینگ + هشدار — ⬜
سه سرویس + workerها + بکاپ با ری‌استارت خودکار؛ مانیتورینگ گام ۲۳ روی دامنهٔ واقعی؛ لاگ با چرخش. **پذیرش:** سه سرویس و workerها زیر `systemd` بالا، بکاپ خودکار سبز و `health` پاسخ‌ده. **اندازه:** M

#### گام ۴۰-۱ — `[F2-5]` 🟠 استقرار خودکار از GitHub (CD) — آپدیت پس از لانچ — ⬜ · ← **خواستهٔ شما: آپدیت خودکار سایت بعد از لانچ**
**هدف:** پس از لانچ، هر تغییر تأییدشده در GitHub بدون دخالت دستی روی سایت بنشیند — با گیت کیفیت، اسموک و رول‌بک.
- **مسیرها:** merge به `main` → CI (تست‌ها) → **auto-deploy به Staging** + اسموک → **Production فقط با تگ نسخه** (یا تأیید دستی در GitHub Environment = تیک تأیید شما).
- **ساخت:** build در CI (نه روی سرور) → artifact → `rsync`/`scp` با **کلید استقرار محدود** (بدون رمز) → ری‌استارت سرویس‌ها با systemd → اسموک روی دامنه.
- **داده:** بکاپ قبل از `prisma migrate deploy`؛ migration خطرناک فقط دستی.
- **بازگشت:** رول‌بک خودکار به آخرین artifact سالم در صورت شکست اسموک + هشدار تلگرام (اتصال به گام ۳۸-۱).
- **رازها:** فقط GitHub Secrets/Environments (`SSH_HOST`/`SSH_KEY`/`DATABASE_URL` deploy)؛ هیچ سری در ریپو نیست.
**پذیرش (شاهد):** (۱) یک PR آزمایشی merge → خودکار روی Staging بالا می‌رود؛ (۲) تگ `v0.0.1-test` → Production با تأیید و اسموک سبز می‌نشیند؛ (۳) با یک تغییر عمداً شکسته، اسموک fail و **رول‌بک خودکار** اجرا می‌شود؛ (۴) هشدار نتیجه در تلگرام می‌رسد. **اندازه:** M · **وابسته به:** گام ۸ (CI)، گام ۳۳/۳۴ (سرور+Staging)، گام ۴۰ (سرویس‌ها).

#### گام ۴۱ — `[F4-8]` کلیدهای واقعی + خرید واقعی — ⬜
کلید پیامک (تست با شمارهٔ خودتان)؛ **خرید واقعی کم‌مبلغ با کارت‌به‌کارت** تا صفحهٔ سفارش (شاهد: سفارش + تأیید + ثبت مالی). Merchant زرین‌پال → پس از لانچ (B-4). **اندازه:** S

#### گام ۴۲ — `[F4-9]` بکاپ زمان‌بندی‌شده + RPO/RTO — ⬜
زمان‌بندی روزانه + رصد `manifest.json` + نگهداری N نسخه + ثبت RPO/RTO تمرین‌شده. **اندازه:** S

#### گام ۴۳ — `[F4-10]` قانونی و اعتماد — ⬜ (بخشی = B-3/B-6)
نمایش اینماد/ساماندهی؛ اطلاعات تماس واقعی؛ مرور نهایی صفحات حقوقی؛ فیلدهای فاکتور مطابق الزام قانونی (اگر برای شما لازم است). **اندازه:** S

#### گام ۴۴ — `[F4-11]` راهنمای اپراتور + Runbook + Rollback — ⬜
راهنمای فارسی کاربری (محصول، سفارش، POS/شیفت، گزارش‌ها، تنظیمات، بکاپ، کاربران) + runbook حوادث (DB down، درگاه down، بکاپ fail، دیسک پر، تعمیر) + برنامهٔ بازگشت نسخه. **اندازه:** M

#### گام ۴۵ — `[F4-12]` چک‌لیست Go/No-Go — ⬜
همهٔ موارد بخش ۶ با شاهد؛ تأیید نهایی شما؛ زمان راه‌اندازی و پشتیبانی مشخص؛ **صفر بودن «ایراد باز» در همهٔ ایستگاه‌ها طبق دروازهٔ بخش ۲.** **اندازه:** S

### ایستگاه ۸ — پس از لانچ

#### گام ۴۶ — `[F5]` رصد پس از لانچ — ⬜
۷۲ ساعت اول: خطاها/کندی/LCP، نرخ پرداخت ناموفق، پیامک‌های ناموفق، تماس‌های پشتیبانی؛ هفتهٔ اول: بکاپ واقعی، reconciliation درگاه، قیف خرید در آنالیتیکس. **اندازه:** مستمر

#### گام ۴۷ — آیتم‌های معوق — ⬜ · ✅ تصمیم #۸: بعد از لانچ
`[F2-4]` کانال‌های انتشار/وبهوک — بعد از لانچ. (دستیار AI و چت‌بات طبق تصمیم #۱۰ به گام‌های ۱۸-۲ و ۱۸-۳ منتقل شدند.)
