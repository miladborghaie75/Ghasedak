# یکپارچه‌سازی منوی حسابداری در سایدبار

## تصمیم کاربر
- همهٔ بخش‌های مالی در **یک گروه «حسابداری»** در سایدبار
- گروه **تاشو شونده** با زیربخش‌ها، نه فهرست تخت
- دامنه: حسابداری + انبار + خرید + خزانه + چک
- بیرون از حسابداری می‌مانند: محصولات، دسته‌ها، برندها، ویژگی‌ها، رسانه، قیمت‌گذاری، سفارش‌ها، پرداخت‌ها، مشتریان، POS

## وضعیت فعلی (پراکنده در ۴ گروه)
| گروه | آیتم‌های مالی |
|---|---|
| فروشگاه | موجودی و انبارگردانی، انبارها، چاپ بارکد، گزارش انبار، خرید از تأمین‌کننده، قیمت‌گذاری |
| POS | ترمینال فروش، فاکتورهای فروش |
| سفارش‌ها | سفارش‌ها، پرداخت‌ها، مشتریان |
| حسابداری | درخت حساب‌ها، سال مالی، اسناد، گزارش سود، خزانه |

## گام ۲ — `apps/admin/components/Shell.tsx`

رندر فعلی فقط `group.items` را نگاشت می‌کند. باید:
۱. `Shell` به کلاینت شود (`"use client"`) تا تاشو/بازشدن state داشته باشد
۲. سرِ گروه، دکمهٔ تاشو باشد با `aria-expanded`
۳. اگر کاربر داخل یکی از زیربخش‌های همان گروه است، گروه **باز بماند**
۴. سرِ گروه با `⌄` بچرخد

منطق «باز ماندن در مسیر فعال»:
```ts
const isActiveGroup = group.children?.some((c) =>
  c.children?.some((leaf) => pathname === leaf.href || pathname.startsWith(leaf.href + "/"))
);
```
`usePathname` از `next/navigation`.

نکته: `Shell` الان یک کامپوننت سرور است که در `page.tsx`ها استفاده می‌شود. تبدیل به کلاینت امن است چون `children` از سرور به‌صورت props می‌آید.

## گام ۳ — `apps/admin/components/MobileNav.tsx`

## مسیرهایی که نباید تغییر کنند
- `/treasury` — صفحهٔ داشبورد مستقیم به آن لینک می‌دهد (`apps/admin/app/page.tsx:140`)
- چک‌ها تبِ داخل `/treasury` هستند (`ChecksWorkspace` در `TreasuryClient.tsx:287`)، پس لینک جداگانه نمی‌سازیم
- همهٔ مسیرهای موجود بدون تغییر کار می‌کنند؛ فقط دسته‌بندی منو عوض می‌شود

## صفحهٔ جدید موردنیاز
`/accounting/journal/new` برای «ثبت سند دستی» وجود ندارد و باید ساخته شود:
- فرم سند: تاریخ، شرح، خطوط (حساب/بدهکار/بستانکار)
- `POST /admin/accounting/journal/manual` با `state: "DRAFT"`
- دکمهٔ «ثبت پیش‌نویس» و «ثبت و قطعی»
- بدون ذخیرهٔ نامتوازن (سرور هم اعتبارسنجی می‌کند)
