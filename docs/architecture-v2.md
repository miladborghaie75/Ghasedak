## ۱) استک پیشنهادی

**بدون تغییر نسبت به فاز قبل — و چرا هنوز درست است:**

| لایه | انتخاب | دلیل (کوتاه) |
|---|---|---|
| فریم‌ورک | Next.js 15 App Router + React 19 + TypeScript | RSC = فیلتر/سئو/سرعت با JS کم؛ type-safety از DB تا UI |
| استایل | Tailwind v4 + توکن CSS | سیستم‌محور، بدون ریسک کلاس‌های متناقض پروتوتایپ |
| داده (فعلاً) | Demo داده ساختاریافته + Repository pattern | UI فقط با تایپ‌ها کار می‌کند؛ تعویض منبع داده = یک فایل |
| داده (فاز واقعی) | PostgreSQL + Drizzle ORM + Zod | مدل رابطه‌ای لازم برای واریانت/سازگاری/موجودی؛ بدون سربار ORM سنگین |
| پرداخت | زرین‌پال (اتصال سرور-به-سرور، مبلغ سمت سرور) | بند ۵۱ — مبلغ هرگز از کلاینت نمی‌آید |
| جستجو | نرمال‌سازی فارسی + جستجوی SQL/pg_trgm؛ مهاجرت بعدی به Meilisearch | ساده‌ترین شروع قابل‌قبول برای فارسی |
| ادمین | پنل اختصاصی سبک روی همان Next (Route `/admin`) | بند ۵۲ — بدون ویرایش کد برای هر محصول |

عدم انتخاب: Medusa (دو اپ + فارسی‌سازی)، WooCommerce (ممنوع در بریف)، микро‌سرویس (بند ۶۴: over-engineering).

## ۲) معماری اپلیکیشن

- **Server Components** برای همه صفحات داده‌محور (خانه/دسته/PDP/جستجو) — فیلتر از query string خوانده و سمت سرور اعمال می‌شود (قابل اشتراک، قابل ایندکس).
- **Client Components** فقط برای تعامل موضعی: Sheet/Drawer، QuickAdd، Wish، stepper، NeedFinder.
- **یک‌جاها (Server Actions در فاز واقعی):** اعتبارسنجی سبد/کوپن/آدرس — قیمت نهایی فقط سمت سرور محاسبه می‌شود.
- **State کلاینت:** فقط سبد/علاقه‌مندی (Context + localStorage اکنون، کوکی سروری بعداً) — بدون Redux/Zustand.

## ۳) مدل داده (بند ۴۰–۴۲ — تغییر کلیدی این نسخه)

```
Category 1─n Product n─1 Brand
Product 1─n Variant
Variant: id, sku, price, salePrice?, stock,
         colorId, sizeTermId, و optionIds دیگر (فنر/اسفنج/کاپ/جنس...)
Attribute (سایز، فنر، اسفنج، کاپ، جنس، رنگ)   ← مفاهیم مستقل (بند ۱۶)
AttributeTerm (75, فنردار, بدون اسفنج, B, پنبه, …)
CategoryAttribute (کدام فیلتر در کدام دسته + ترتیب)   ← بند ۱۹
SizeGuide (per category/brand)   ← بند ۱۵
Cart/CartItem, Order/OrderItem (snapshot قیمت/آدرس), Customer/Address,
ShippingMethod, PaymentMethod, Coupon, Review (تایید ادمین), FAQ, ContentBlock
```

**سازگاری ترکیبی (بند ۴۱):** موجودی فقط روی Variant تعریف می‌شود. UI برای یک رنگ،
سایزهایی را فعال نگه می‌دارد که Variant (رنگ∩سایز) موجود داشته باشند — نه غیرفعال‌سازی سراسری.
Demo داده از نوع `Variant[]` با همین قاعده ساخته می‌شود.

**Brands** موجودیت مستقل (بند ۲۲) — نه attribute.

## ۴) معماری کامپوننت

لیست بند ۵۴ تقریباً همان پیاده‌سازی فعلی است؛ تغییرات:
- `HeroDrawer` بازطراحی با کپی و واکنش‌گرایی جدید (بند ۸)
- `NeedFinder` + `NeedFinderOption` جدید (بند ۹)
- `FilterGroup` → گروه‌بندی بصری «نوع سوتین» (بند ۱۷) با داده‌های مستقل (بند ۱۶)
- `FilterChip` + «حذف همه» جدید (بند ۲۰)
- `ColorSwatches` وابسته به سازگاری واریانت (بند ۱۲/۴۱)
- حذف نسخه‌های تکراری — یک ProductCard/Sheet/Drawer برای همه‌جا (بند ۵۶)

## ۶) استراتژی واکنش‌گرا

Mobile-first؛ گرید محصول ۲/۳/۴؛ هدر دو‌ردیفه موبایل (بند ۳۱)؛
Drawer فیلتر از راست در موبایل؛ Sticky CTA فقط PDP موبایل؛
QA اجباری در ۳۹۰/۷۶۷/۱۰۲۴/۱۴۴۰ (بند ۶۱).

## ۷) استراتژی دیزاین‌سیستم

توکن‌های بند ۳۳–۳۶ (شامل دو رنگ جدید Sage `#8FA89B` و Dusty Rose `#C9829D`
برای بج سبد و لهجه‌های خاص — نه جایگزین primary).
**مقیاس وزن فونت اصلاح می‌شود:** 400/500/600/700 (بند ۳۴) — فایل‌های فعلی به 500/700
وزن‌دهی شده‌اند که به 500/600/700 نرمال می‌شود.
Clay فقط در Hero/آبجکت دسته/CTA خاص (بند ۳۷)؛ کارت‌ها radius 16، border ظریف، بدون سایه سنگین.

## ۸) فازها

مطابق بند ۵۹؛ موقعیت فعلی: فازهای ۱–۱۴ دارای پیاده‌سازی اولیه‌اند.
**پس از تایید این گزارش، اجرای Gap-Work به این ترتیب:**
`فیلتر/مدل‌داده (۶/۹/۱۶–۲۰) → NeedFinder (۱۳) → Hero (۴) → Header (۳) → ProductCard/QuickAdd (۷) → PDP (۱۰) → Checkout (۱۲) → QA (۱۶–۲۰)`

## ۹) ریسک‌های فنی

1. **سازگاری واریانت** — پیچیده‌ترین بخش UI؛ با ماتریس مشتق از Variant[] حل و با QA بند ۶۲ تست می‌شود.
2. **جستجوی فارسی** — نرمال‌سازی (ی/ک/نیم‌فاصله) لازم است؛ اکنون پیاده شده.
3. **RTL در Sheet/Drawer** — جهت بازشدن باید از راست باشد؛ تست بصری الزامی.
4. **قفل بودن مستندات روی "WooCommerce" در متن پروتوتایپ** — طبق بند ۱، فقط مرجع UX؛ در کد اثری ندارد.
5. **داده واقعی صفر** — همه سکشن‌های «پرفروش/تخفیف/نظر» گیت می‌خورند تا داده واقعی وجود دارد.
