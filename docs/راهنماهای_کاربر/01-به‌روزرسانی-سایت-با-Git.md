# راهنمای به‌روزرسانی سایت با Git (همگام‌سازی لوکال ←→ هاست)

هدف این راهنما اینه که بتونی با کمترین دردسر و فقط با چند دستور، تغییرات پروژه رو از سیستم محلی به هاست منتقل و سایت رو به‌روز کنی.

## ۱. چرا از Git استفاده می‌کنیم؟

- **فقط فایل‌های تغییر یافته** منتقل میشه
- **منبع واحد** برای کد: همیشه هم لوکال و هم هاست یکی هستن
- **کم‌خطر و قابل پیگیری**: هر آپدیت تاریخچه داره و میشه برگردوند
- **هماهنگ با روش استقرار پروژه**: دقیقاً همون چیزی که توی [`docs/deploy-guide.md`](../deploy-guide.md) هم پیشنهاد شده

## ۲. پیش‌نیازها

قبل از شروع حتماً این چیزها آماده باشن:

| مورد | توضیح |
|---|---|
| **ریپو خصوصی Git** | مثلاً GitHub، GitLab، Bitbucket یا هر گیت‌سرور دیگه‌ای |
| **دسترسی SSH به هاست** | میشه با `ssh user@ip-server` وارد بشی |
| **کلید SSH** | بین سیستم محلی و هاست/گیت‌سرور تنظیم شده باشه |
| **Git روی لوکال و هاست** | روی هر دو نصب شده باشه (`git --version`) |
| **Node.js + pnpm** | مطابق با پروژه روی هاست نصب شده باشه |

## ۳. بار اول (فقط یک‌بار)

فقط دفعه اول این قدم‌ها رو انجام میدی.

### گام ۳.۱. آماده‌سازی کلید SSH

**روی سیستم محلی:**

```bash
ssh-keygen -t ed25519 -C "your-email@example.com"
cat ~/.ssh/id_ed25519.pub
```

کلید عمومی (`.pub`) رو کپی کن و توی گیت‌سرور (Settings > SSH Keys) اضافه کن.

**روی هاست:**

همین کلید عمومی رو توی `~/.ssh/authorized_keys` هم اضافه کن تا مستقیم بتونی SSH بزنی.

### گام ۳.۲. کلون کردن ریپو روی هاست

با SSH وارد هاست شو و ریپو رو کلون کن. معمولا مسیر پیشنهادی اینجاست:

```bash
ssh user@IP-SERVER
cd /opt
git clone git@github.com:USERNAME/REPO-NAME.git ghasedak
cd ghasedak
```

> اگه قبلاً فایل‌ها رو دستی آپلود کردی، بهتره یا کلون کنی و فایل‌های حساس رو دستی کپی کنی، یا داخل همون مسیر `git init` + `git remote add origin ...` کنی.

### گام ۳.۳. بررسی فایل‌های حساس

فقط یک بار مطمئن شو این فایل‌ها **نباید داخل Git برن**. فایل‌های حساس باید دستی روی هاست بمونن:

| فایل/پوشه | دلیل |
|---|---|
| `.env` | متغیرهای محیطی سرور |
| `.env.local` | متغیرهای لوکال/API |
| `apps/api/.env.local` | کلیدهای حساس API (SMTP، ... ) |
| `apps/api/.storage/` | فایل‌های آپلود شده |
| `apps/data/media/` | رسانه‌های سایت |
| `node_modules/` | وابستگی‌ها (با `pnpm install` نصب میشه) |
| `.next/` | بیلد فروشگاه/ادمین |
| `dist/` | بیلد API |
| `.turbo/` | کش Turborepo |

اگه این فایل‌ها توی `.gitignore` نیستن، حتماً اضافه‌شون کن.

## ۴. کار روزانه (به‌روزرسانی سایت)

هر بار که تغییری توی کد انجام دادی، همین چرخه رو تکرار کن.

### گام ۴.۱. از سیستم محلی

داخل ریشه پروژه باز کن و کامیت + پوش کن:

```bash
# بررسی تغییرات
git status

# اضافه کردن همه تغییرات
git add .

# کامیت با توضیح مشخص
git commit -m "feat: توضیح تغییر انجام شده"

# ارسال به ریپو
git push origin main
```

> سعی کن توضیح کامیت فارسی یا انگلیسی کوتاه و روشن بنویسی تا بعداً راحت‌تر پیداشون کنی.

### گام ۴.۲. از هاست (آپدیت + بیلد + ری‌استارت)

با SSH وارد هاست شو:

```bash
# ورود به مسیر پروژه
cd /opt/ghasedak

# دریافت آخرین تغییرات
git pull origin main

# نصب وابستگی‌های جدید در صورت نیاز
pnpm install

# بیلد همه اپ‌ها
pnpm -r build

# ری‌استارت سرویس‌ها
sudo systemctl restart ghasedak-api ghasedak-storefront ghasedak-admin
```

> اسم سرویس‌ها ممکنه توی هاستت کمی متفاوت باشه. اگه مطمئن نیستی با `systemctl list-units | grep ghasedak` بررسی کن.

همین‌که این دستورات تموم شدن، سایت بلافاصله با تغییرات جدید بالا میاد.

## ۵. چک‌لیست سریع

قبل از آپدیت نهایی اینارو چک کن:

- [ ] **لوکال**: تغییرات رو تست کردی و هیچ ارور TypeScript نداره
- [ ] **Git**: `git push` با موفقیت انجام شده
- [ ] **هاست**: `git pull` بدون کانفلیکت تموم شده
- [ ] **بیلد**: `pnpm -r build` بدون خطا پایان یافته
- [ ] **ری‌استارت**: سرویس‌ها ری‌استارت شدن
- [ ] **تست**: سایت باز شده و تغییرات دیده میشه

## ۶. عیب‌یابی رایج

| مشکل | علت احتمالی | راه حل |
|---|---|---|
| **`Permission denied (publickey)`** | کلید SSH تنظیم نشده یا اشتباهه | کلید عمومی رو توی گیت‌سرور و هاست بررسی کن |
| **`CONFLICT` هنگام `git pull`** | فایل روی هاست دستی ویرایش شده | اول بررسی کن با `git diff` یا `git status`. اگه میشه فایل دستی رو کم کن و فقط از Git استفاده کن |
| **`pnpm install` طولانی یا ارور** | کش خراب یا نسخه pnpm متفاوت | با `corepack prepare pnpm@10.12.1 --activate` نسخه رو هماهنگ کن (طبق [`docs/deploy-guide.md`](../deploy-guide.md)) |
| **سایت بالا نیومده بعد ری‌استارت** | سرویس کرش کرده | لاگ سرویس رو ببین: `journalctl -u ghasedak-api -n 50 --no-pager` |
| **فایل `.env.local` پاک شده** | اشتباهاً سینک شده | هرگز این فایل رو کامیت نکن. دستی کپی‌ش کن و توی `.gitignore` بررسی شه |
| **`next build` ارور می‌ده** | متغیرهای `NEXT_PUBLIC_*` تغییر کردن | اگه متغیر عمومی تغییر دادی حتماً باید `build` دوباره انجام شه (همین کاری که بالا گفتیم) |

## ۷. توصیه‌های نهایی

- **فقط از Git استفاده کن**: تا حد ممکن از آپلود دستی فایل پرهیز کن. کم‌ترین اشتباه اینجاست.
- **فایل‌های حساس رو هرگز کامیت نکن**: مخصوصاً `.env.local` و کلیدهای SMTP.
- **قبل از بیلد حتماً `git pull` کن**: اگه چند نفر روی پروژه کار می‌کنن این خیلی مهمه.
- **یک اسکریپت بساز**: اگه می‌خوای یه ضرب بزن بری، میشه یه فایل `update.sh` روی هاست بنویسی و دستورات گام ۴.۲ رو داخلش بریزی.
