**تاریخ:** ۲۰۲۶-۱۰-۳۰ · **برنچ:** `audit-and-optimization` · **نقطهٔ شروع:** `a5edb89`
**دامنهٔ بررسی:** کل مونوریپو (۷۹۹ فایل ردیابی‌شده) + محیط تولید (فقط خواندنی)

> این گزارش نتیجهٔ فاز ۱ مأموریت است: شناسایی پشته، معماری، مسیرها و ریسک‌ها.
> هیچ نتیجهٔ تست رفتاری در این سند ادعا نشده؛ همهٔ موارد «نیازمند تأیید در فاز ۳» برچسب خورده‌اند.
> تست‌های موجود پروژه اجرا نشده‌اند و مبنای هیچ ادعایی نیستند (طبق قانون دوم مأموریت).

## ۲) نقاط قوت تأییدشده (بر پایهٔ خواندن کد و بازرسی محیط)

1. **بهایابی سمت سرور:** قیمت واحد و جمع سفارش در `apps/api/src/orders/orders.service.ts` از DB خوانده می‌شود، نه از بدنهٔ درخواست.
2. **تأیید پرداخت سمت سرور و idempotent:** `apps/api/src/payments/payments.service.ts` مبلغ را از `PaymentAttempt` می‌خواند و verify دوباره را کوتاه می‌کند.
3. **کنترل دسترسی:** `PermissionsGuard` هم متادیتای کلاس و هم هندلر را می‌خواند؛ حالت «بدون مجوز = باز» با دکوراتور صریح مدیریت می‌شود.
4. **CSRF:** double-submit + بررسی Origin/Referer با لیست مبدأهای مجاز (`csrf.guard.ts`).
5. **هدرهای امنیتی:** helmet روی API، هدرهای پایه در فروشگاه/پنل، HSTS در nginx.
6. **محدودسازی نرخ:** قواعد دقیق برای login/checkout/payment/OTP/AI با ذخیره‌ساز مشترک DB و fallback حافظه‌ای.
7. **رسانه:** جلوگیری از path traversal با whitelist نام فایل در `media-serve.controller.ts`.
8. **پشتیبان‌گیری:** cron روزانه ۰۲:۰۰ + تست بازیابی هفتگی (`/root/ghasedak-deploy/backup.sh` و `restore-test.sh`)؛ پشتیبان‌ها تا امروز موجودند.
9. **صفحه‌ساز:** بلوک‌ها HTML خام رندر نمی‌کنند (بدون `dangerouslySetInnerHTML` در `packages/blocks`).
10. **CI:** نصب frozen، typecheck/build سه اپ و تست API روی پستگرس تازه در هر اجرا.

## ۴) برنامهٔ تست مستقل (فاز ۳) — بدون استفاده از تست‌های قدیمی

محل جدید: `audit/` (جدا از `apps/*/test`). اجرای مستقل با Node 22+ و صفر وابستگی به jest پروژه.

| لایه | ابزار | نمونهٔ سناریو |
|---|---|---|
| API | runner اختصاصی `audit/lib/runner.mjs` + fetch | ۲۰۰+ مورد: کاتالوگ، سبد، سفارش، پرداخت mock، کد تخفیف، مرجوعی |
| DB | psql/Prisma روی DB ایزوله | صحت موجودی، Ledger، قیدهای یکتایی، مهاجرت تازه |
| Auth | fetch + cookie jar | ورود/خروج، انقضای نشست، بازیابی رمز، OTP mock |
| AuthZ | ماتریس نقش×مسیر | دسترسی مستقیم مشتری به API ادمین، IDOR سفارش/آدرس |
| E2E | puppeteer-core + Chrome نصب‌شده | خرید مهمان: خانه→محصول→سایز/رنگ→سبد→تسویه→mock→سفارش در پنل |
| UI | puppeteer (viewport موبایل/دسکتاپ) | سرریز افقی، فوکوس، کنتراست، RTL |
| Security | اسکریپت اختصاصی | CSRF، هدرها، rate limit، آپلود فایل، XSS در فیلدهای متنی |
| Performance | Chrome DevTools Protocol + curl | TTFB/FCP/LCP/CLS صفحات کلیدی، اندازهٔ JS/CSS، زمان پاسخ APIها |
| Regression | snapshot پاسخ‌ها | تغییر ناخواستهٔ قیمت/موجودی/محتوای صفحات |

**محیط پیشنهادی (ایزوله، بدون دست‌زدن به دادهٔ تولید):**
- دیتابیس `ghasedak_audit` روی همان VPS (جدا از `ghasedak`)، فقط از طریق تونل SSH روی پورت محلی ۵۴۳۳.
- مهاجرت‌ها + seed دمو (`SEED_DEMO=true`)، پرداخت `GHASEDAK_MOCK_GATEWAY=1`.
- API روی ۴۰۱۰، فروشگاه روی ۳۱۲۲، پنل روی ۳۲۱۰ (پورت‌های تولید دست‌نخورده).
- تست‌های بار/حجمی فقط روی همین محیط محلی؛ علیه تولید اجرا نمی‌شود.

## ۵) نیازها و تصمیم‌های لازم

1. **تأیید ساخت دیتابیس ایزولهٔ `ghasedak_audit` روی VPS** (بدون هیچ نوشتنی روی `ghasedak`) یا انتخاب نصب PostgreSQL محلی.
2. **تأیید نصب Playwright** در صورت نیاز به سناریوهای پیچیده‌تر از puppeteer-core (فعلاً puppeteer-core + Chrome موجود کافی است و نصب لازم نیست).
3. **دسترسی به محیط Sandbox درگاه پرداخت** لازم نیست؛ مسیر mock پروژه برای تست تأییدشده است.
4. **استقرار هر اصلاح روی تولید فقط پس از تأیید صریح شما** (طبق قانون نهم مأموریت).

## ۶) محدودیت‌های این گزارش

- هیچ تست رفتاری (API/E2E/کارایی/امنیت فعال) در این فاز اجرا نشده؛ جدول بخش ۳ فقط نتیجهٔ بازرسی کد و محیط است.
- تست‌های موجود پروژه عمداً اجرا نشده‌اند؛ تنها یک تست برای تأیید F2 اجرا شد و آن هم مبنای «سلامت سیستم» نیست.
- اعداد کارایی و نتایج امنیتی فعال در فازهای بعدی و با شاهد خام (لاگ/خروجی) ارائه می‌شوند.
